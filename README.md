# Ternopil EpiGIS

Вебінструмент для епідеміологічного картографування Тернопільської області.

## Поточний MVP

- Інтерактивна карта на Leaflet / OpenStreetMap.
- Демонстраційні записи (умовні, не реальні випадки).
- Фільтри за нозологією, територіальною громадою, датами та статусом.
- Реєстр випадків і картка вибраного запису.
- Імпорт XLSX/XLS/CSV у браузері з базовою валідацією.
- Єдина Excel-книга-сховище з аркушами `Cases`, `Healthcare`, `Water`, `Food`, `Natural`, `Outbreaks`, `BioMonitoring`, `Meteorology`, `Population`, `GeoLayers`, `Instructions` та `DataDictionary`.
- Excel-книга формується з поточних даних браузера: випадків, предметних реєстрів і GeoJSON-шарів; після імпорту дані залишаються у локальному сховищі браузера.
- Імпорт оновлює лише набори, чиї аркуші присутні у книзі; аркуші з некоректними записами реєстру або пошкодженими GeoJSON не перезаписують чинні дані.
- Фільтри предметних реєстрів: тип реєстру, пошук за атрибутами, громада, тип об’єкта та діапазон дат.
- Завантаження Excel-книги та експорт поточної вибірки випадків у CSV.
- Географічні шари GeoJSON із точками, лініями та полігонами; керування видимістю та локальне збереження у браузері.
- Нова структура предметних реєстрів: заклади охорони здоров’я, водна інфраструктура, харчові об’єкти, природні об’єкти, епідеміологічні вогнища, біологічний моніторинг, метеорологія та агреговані дані населення.
- Вибір предметного реєстру для категоризації наступного GeoJSON-імпорту; описані типи геометрій і атрибутивні поля кожного реєстру.
- Локальні форми CRUD для восьми предметних реєстрів: створення, редагування та видалення записів із перевіркою обов’язкових полів і координат; точкові записи відображаються на карті.
- Перейменування шарів і масштабування карти до меж вибраного шару.
- Табличний перегляд результатів просторового перетину з типом геометрії, кількістю перетинів і доступними атрибутами об'єктів.
- Ручне креслення точок, ліній і полігонів на карті.
- Побудова буферних зон навколо геометрій у метрах (Turf.js; геодезична відстань).
- Просторовий перетин двох GeoJSON-шарів: пошук об'єктів, що геометрично перетинають вибрану зону; результат зберігається як окремий шар.
- Дані імпорту й створені шари обробляються лише в браузері та не передаються до серверної бази.

## Сумісність і межі поточного етапу

- Попередній реєстр випадків, формат `GISLayer`, ключ локального сховища `ternopil-epigis-layers-v1`, ручне креслення, буферизація та просторові перетини збережені без міграції чи видалення.
- Записи предметних реєстрів наразі зберігаються у браузері в `localStorage` (`ternopil-epigis-registry-records-v1`); це локальний MVP без синхронізації між користувачами та пристроями.
- Лінійні та полігональні об'єкти додаються через GeoJSON; ручне креслення залишається в універсальному модулі шарів. Серверне збереження, права доступу та аудит ще не реалізовані.
- Для реєстру населення допускаються лише агреговані територіальні дані; персональні медичні дані не завантажувати.

## Локальний запуск

Потрібен Node.js 20 або сумісна актуальна LTS-версія.

```bash
npm install
npm run dev
```

Для перевірки production-збірки:

```bash
npm run build
npm run preview
```

## Розгортання на Cloudflare (підключення до чинного Worker)

Проєкт уже має `wrangler.jsonc` із назвою Worker `ternopil-epigis` та каталогом статичних файлів `dist/`. Щоб оновлювати саме чинний Worker `https://ternopil-epigis.burdataras.workers.dev/`, підключи репозиторій через **Workers Builds**:

1. Відкрий Cloudflare Dashboard → **Workers & Pages** → вибери наявний Worker **ternopil-epigis**.
2. Перейди в **Settings → Builds** і натисни **Connect**.
3. Авторизуй GitHub / Cloudflare GitHub App, якщо система попросить, і вибери репозиторій `TarasB88/ternopil-epigis`.
4. Встанови production branch: `main`.
5. Параметри збірки:
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy`
   - Root directory: `/`
6. Збережи налаштування та запусти build/deploy. Cloudflare має використовувати `wrangler.jsonc` з репозиторію.

**Критично:** ім'я Worker у Cloudflare має точно збігатися з полем `name` у `wrangler.jsonc` — `ternopil-epigis`. Підключення існуючого Worker не створює окремий Pages-сайт. Cloudflare Workers Builds за замовчуванням може автоматично створити build-токен; не потрібно передавати API-токен у GitHub Actions чи зберігати його в репозиторії.

Після успішного першого розгортання кожен новий push у `main` автоматично запускатиме збірку та деплой на цей Worker.

### GitHub Actions у цьому репозиторії

Workflow **Build EpiGIS release artifact** виконує перевірку `npm run build` і зберігає артефакт `ternopil-epigis-dist`. Він не публікує Worker самостійно: це робить Workers Builds після підключення GitHub у Cloudflare Dashboard. Артефакт потрібен як резервна збірка, а не як обов'язковий крок деплою.

### Альтернатива: Cloudflare Pages

Pages — окремий варіант хостингу. Якщо створити Pages-проєкт із цим репозиторієм, задай Build command `npm run build` і Build output directory `dist`. Це буде окремий сайт із власним доменом/маршрутом, а не оновлення чинного Worker.

## Географічні шари та буферний аналіз

- GeoJSON імпортується як `Feature` або `FeatureCollection`; підтримуються `Point`, `MultiPoint`, `LineString`, `MultiLineString`, `Polygon` і `MultiPolygon`. Перевіряється структура Feature, тип геометрії та діапазони координат довготи/широти; некоректні об'єкти відхиляються.
- Шари можна вмикати/вимикати, видаляти та експортувати окремо у GeoJSON. Ручно створені об'єкти зберігаються як GeoJSON.
- Для буферизації вибирається шар і відстань у метрах (від 1 до 100 000 м). Результат додається як окремий шар, вихідні дані не змінюються.
- Для просторового перетину вибираються шар зони та шар цільових об'єктів. У результат потрапляють цільові об'єкти, геометрії яких перетинаються хоча б з однією геометрією зони; у властивостях зберігається кількість перетинів. Аналіз працює з геометріями GeoJSON і не визначає юридичний статус зони чи епідеміологічний причинно-наслідковий зв'язок.
- Шари зберігаються у `localStorage` конкретного браузера. Це не спільне сховище: дані не синхронізуються між користувачами або пристроями.
- Буфер — геометричний аналітичний результат, а не автоматично встановлена санітарно-захисна чи нормативна зона.

## Формат імпорту

Обов'язкові поля: `disease`, `date`, `hromada`, `latitude`, `longitude`.

Рекомендовані поля: `id`, `settlement`, `status`, `age`, `sex`, `notes`.

Підтримуються також окремі українські заголовки: `нозологія` / `діагноз`, `дата`, `громада` / `територія`, `широта`, `довгота`, `населений пункт`, `вік`, `стать`, `примітки`.

## Важливо про конфіденційність

Ця версія є клієнтським MVP без серверної бази даних і без автентифікації. Імпортовані дані залишаються в пам'яті вкладки браузера, але карта використовує зовнішні тайли OpenStreetMap, а шрифти завантажуються з Google Fonts. Не завантажуй персональні або медично ідентифіковані дані до налаштування контролю доступу, оцінки безпеки та політик зберігання. Для робочого використання потрібно додати Cloudflare Access, захищене API та серверне сховище, а також перевірити відповідність вимогам захисту персональних даних.

## Roadmap

1. Імпорт SHP/ZIP, CSV/Excel із координатами та зіставлення колонок.
2. Збагачення просторових перетинів атрибутами громад, населених пунктів, чисельності населення та медзакладів.
3. Офіційні довідники медзакладів, інфраструктури, природних і метеорологічних шарів.
4. Cloudflare Worker API, D1/R2, Cloudflare Access і ролі користувачів.
5. Часові ряди, звіти та аналіз просторових скупчень із чітким розмежуванням сигналу й підтвердженого спалаху.
